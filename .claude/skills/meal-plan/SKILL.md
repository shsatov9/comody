# 献立を組む

チラシの特売品から平日3日の夕食を組み、土日の買い物リストを出す。

設計は [`docs/DESIGN.md`](../../../docs/DESIGN.md) §5。ここはその手順だけを書く。

## この所帯の決まり

| | |
|---|---|
| 対象 | **月・水・金の夕食だけ。** 火・木は作らない |
| 人数 | 2人。**栄養は1人前**で出し、**分量と金額は2人分**で出す |
| 買い物 | **土日に1回だけ** |
| 調理時間 | **30分。** 材料を出してから食卓に出るまでで、解凍時間を含まない |
| 作り置き | **しない。** 土日の作業は小分け冷凍だけ |
| 食べないもの | **キノコ類**（しめじ・エリンギ・なめこ・マッシュルーム等）と**貝類**。貝から出汁も取らない。オイスターソースは可 |
| 目標 | ダイエット中なのは1人だけ。だから栄養は1人前で出し、その人の目標とだけ比べる |

**5日ではなく3日。** 最初は5日で組んだが「5日間自炊はつらい」と返ってきたので減らした。
作らない日を後から諦めるのではなく、最初から織り込む。月・水・金にするのは、2日
続けて作らずに済むため（月火水だと3日続きで、減らした意味が薄い）。

## 特売をメインに、足りないものは通常価格で

**特売品だけでは組めない。** 実物のチラシは野菜が長ねぎ1品だけ、ということが起きる。
定番品を混ぜてよい。ただし線引きがある。

> **主菜のたんぱく源は特売品から取る。** 副菜・薬味・米・調味料は通常価格でよい。

金額の比率では縛らない。肉と魚だけで買い物の半分を超えるので、**そこさえ特売なら
食費は効く。** 野菜を何割特売にしたかはほとんど響かない。

## 3日ぶんは「3回の提案」ではなく「1回の買い物の割り付け」

日を独立に組むと買い物がばらけて、1回の買い物で回らなくなる。

- **同じ食材を複数日にまたがって使い切る**（鶏もも 1kg を水と金に割る）
- **傷みやすさで順番を決める**
- **1回の買い物で回る**

土曜に買った場合の持ちかた。

| | |
|---|---|
| 魚（生） | 買った翌日まで → 月曜に置く |
| 漬け魚（西京漬・塩麹漬） | 3〜4日 → 水曜にも置ける |
| 生の肉 | 2日まで |
| それ以降（水の一部・金） | 冷凍から回す |

自然と「月＝魚、水＝生の肉の限界、金＝冷凍」に寄るが、**この並びを型として固定
しない。** 毎週同じ形になって飽きる。特売が魚だらけの週は月と水が魚でいい。

## 3日にすると、特売のパック単位が余る

特売は「若鶏もも肉 4枚以上 100g当り89円」のように**パック単位**で安い。5日なら
1kg を使い切れたが、3日だと2食ぶん（660g）しか要らず余る。

**余りは献立の外に置く。** 買い物リストには買う量をそのまま書き、使い切れない分は
冷凍して翌週へ回すと書く。無理に3日へ詰め込むと1食の量が増えて、目標から外れる。

## 冷凍と、前夜の解凍

**冷凍するかどうかは買い物リスト側に書く。** 買った瞬間の判断なので、金曜の献立を
見るときには間に合わない。

```
若鶏もも肉 1,000g  →  330g ずつ2つに分けて冷凍（水・金）。残りは翌週へ
```

**前夜の解凍は献立側に1行で書く。** 30分・作り置きなし・水と金は冷凍肉、が揃うと、
前夜に冷蔵庫へ移す作業が献立の一部になる。金曜の夕方に凍った肉を見つけた時点で
その日の献立は成立しない。**書き忘れると週の後半が丸ごと崩れる。**

## 栄養は成分表から計算する。目分量で出さない

`lib/food/` に `food` リポジトリから写した274食品の成分表（八訂出典）と、名前の
突き合わせ・分量のグラム換算・集計がある。**材料と分量を書き出して、そこへ通す。**

```js
import { buildIndex } from './lib/food/nutrition/db.js';
import { resolveItems, calculateRecipe } from './lib/food/nutrition/calc.js';

const index = buildIndex();
const rows = resolveItems([{ name: '鶏もも肉', quantity: '330g' }, ...], index);
const r = calculateRecipe(rows, 2);   // 2人分 → perServing が1人前
```

**目分量との差は大きい。** 同じ料理で 545 kcal・脂質 14g と見積もったものが、計算
すると 638 kcal・脂質 30g だった。脂質は2倍以上ずれる。

**計算したから正しい、ではない。** 274件に無い食材は近い名前に化ける（「めかぶ」が
「かぶ」に落ちた）。`rows[].match.confidence` が `high` でないものと、
`counts.unmatched` は必ず目視して、外れていたら書き方を変えるか正直に書く。

```
鶏もも肉 皮なし    -> chicken_thigh_skinless   正しい
鶏もも肉(皮なし)   -> chicken_thigh            括弧書きは効かない
```

## チラシの落とし穴

実物を読んで確かめたもの。

- **チラシの期間 ≠ 商品の期間。** 同じ紙面に「9/9 水 限り」（単日）「9/10 木より
  販売」（途中から）「16時からの夕方できたて市」（時間帯）が並ぶ。しかも
  **生鮮の主力が単日特売**だった。土日に買うなら、**土日に有効な品だけ使う**
- **土曜と日曜で目玉が丸ごと別のことがある。** 「9/12 土 限り」と「9/13 日 限り」で
  安い肉も野菜も違った。**どちらに行くかを決めないと献立が決まらない**
- **数量制限。** 「1家族様各1点限り」「先着100名様限定」。買い物リストがこれを
  超えると店で買えない
- **コモディイイダには水〜金の3日号もある。** 期間に土日が入っていない号を渡され
  たら、**まずそれを指摘する**
- **特売の野菜がほとんど無い週がある。** 定番品で補う
- **平日に回せる魚が無い週がある。** 生さんまも刺身も買った翌日まで。漬け魚か塩鮭が
  無ければ、魚は月曜の1日だけになる
- **目玉が脂の多い部位（牛バラ・豚バラ）に寄る週がある。** 勝手に鶏むねへ
  差し替えない。**そのまま組んで、栄養の数字で見せる。** 差し替えたら特売から
  組む意味がなくなる

## 読み取りの自信

自信のない箇所も、自信のある箇所と同じ調子で出てくる。小さい文字（内容量、正式な
商品名、割引率がどの品に掛かるか、枠線がどこまで掛かるか）は実際に読めない。

**読めなかったものは読めなかったと書く。** 献立に使う肉・魚・野菜は大きい表示の
ことが多いので、そこは確度が高い。低いのはたいてい菓子・加工品の側。

## 出す形

1. **献立の表** — 日 / 料理 / 調理時間 / 前夜にやること（3日ぶん）
2. **1人前の栄養** — kcal / P / F / C / 食塩。**成分表から計算した値**
3. **代替案** — 各日2つ。**同じ買い物リストで成立するもの**
4. **買い物リスト** — 特売品と定番品を分け、税込で。定番品の価格は推定と明記
5. **帰宅後に冷凍するもの**
6. **使い切りの確認** — 余りが出るなら書く（3日だとパック単位で必ず余る）
7. **読めなかったところ・計算で外れたところ**

## 出す前に照合する

- 献立に出る食材が、全部買い物リストにあるか
- **各日の主菜が、特売品を1つ以上使っているか**
- 買った量と使う量が合うか。余りを黙って消していないか
- キノコ類・貝類が混ざっていないか（**出汁も見る**）
- どの日も30分以内か（解凍時間は数えない）
- 冷凍から回す日に、前夜の解凍が書いてあるか
- **栄養の一致がすべて `high` か。`unmatched` が 0 か**

## 保存する先

DB に入れる段になったら `meal_plans` / `meal_plan_items` /
`meal_plan_item_ingredients` / `shopping_items`。作る日だけ行を置き、作らない日は
行を作らない（画面が「作らない日」と出す）。栄養値は**推定として**入れる。
詳細は `docs/DESIGN.md` §5。
